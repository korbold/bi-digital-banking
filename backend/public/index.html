Cómo encaja

App Flutter  (reintentos · circuit breaker · caché)
  ├─▶ Firebase Auth / Remote Config
  ├─▶ WebView ─puente JS─▶ micro-app de seguros
  └─HTTPS + ID token─▶ BFF (Vercel Function, TypeScript)
                         ├─▶ Cloud Firestore   clientes, cuentas, movimientos
                         ├─▶ Firebase Cloud Messaging   push
                         └─▶ open.er-api.com   tipos de cambio

Endpoints

MétodoRutaQué hace
GET/api/health públicoLiveness
GET/api/status públicoEstado de dependencias
GET/api/mePerfil del cliente; 404 onboarding_required si no existe
POST/api/onboardingAlta idempotente: segmentación y cuentas con movimientos iniciales
PATCH/api/me/preferencesIntereses del cliente
GET/api/accountsCuentas y saldos
GET/api/accounts/{id}/movementsMovimientos paginados por cursor
GET/api/beneficiaries/lookupVerifica un número de cuenta y devuelve el titular enmascarado
POST/api/transfersTransferencia atómica entre cuentas propias o a terceros; exige Idempotency-Key
GET/api/homePantalla server-driven personalizada por segmento, uso y gasto
POST/api/eventsSeñales de comportamiento para personalizar
POST/api/devicesRegistro de token FCM
POST/api/notifications/testPush de prueba al usuario
GET/api/fxTipos de cambio (servicio externo)
POST/api/insurance/quoteCotización usada por la micro-app de seguros

Salvo los públicos, todos exigen Authorization: Bearer <Firebase ID token>. Errores: {"error":{"code","message"}}.
